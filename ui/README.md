# Settings UI (ui/)

The settings window for Blue Baton: hosts, input devices, pairing, diagnostics. React + TypeScript, Tailwind CSS,
and [shadcn/ui](https://ui.shadcn.com) components, built with Vite into static files (`dist/`).
The same build runs in three places: the menu bar app (`../app`), the dev bridge (`../firmware/tools/bridge.py`),
and a Chrome/Edge page served from localhost or HTTPS, through Web Serial.

Layers: transport (app, USB, bridge, mock) → protocol client → store → React views. The board logic is plain
JavaScript in `src/lib/board/` (no React), so it is tested with Node and reused unchanged by every transport.

## Develop

```bash
npm install
```

```bash
npm run dev
```

Open `http://localhost:5180/?mock` for the mock board (`&lang=ko` for Korean, `&fast` for 10 s scans).
Inside the menu bar app (`npm run dev` in `../app`) the window loads this dev server and talks to the real board.

```bash
npm run build
```

```bash
npm test
```

## Transports

| Where | Transport | Notes |
|---|---|---|
| Menu bar app | `transport/tauri.js` | The app owns the USB port (`app/src-tauri/src/board.rs`); lines arrive as events |
| Dev bridge | `transport/bridge.js` | `?bridge`. Server-sent events + POST. The UI, monitors, and the flash helper share one port |
| Browser | `transport/webserial.js` | Chrome/Edge only. A port allowed once opens without the picker next time |
| No board | `transport/mock.js` | `?mock`. Imitates the mouse and keyboard captured from real hardware and the pairing methods not tried on hardware |

## Files

| Path | Role |
|---|---|
| `src/App.tsx`, `src/components/*` | Views: header, board connect card, hosts (the baton), input devices, dialogs (add host, add device, confirm), diagnostics, and the menu bar panel (`Panel.tsx`) |
| `src/components/ui/*` | shadcn/ui components (generated by `npx shadcn add`, then left as is except imports) |
| `src/index.css` | Tailwind and the Blue Baton theme (shadcn CSS variables; light, and ink navy for dark) |
| `src/lib/board/controller.js` | Board link, store, and all actions; tray sync inside the app |
| `src/lib/board/protocol.js` | Line-JSON commands, replies, and events (`firmware/PROTOCOL.md`) |
| `src/lib/board/store.js` | UI state. Changes only through board replies and events |
| `src/lib/board/inputs.js` | Input monitor (plain DOM: it updates dozens of times a second) |
| `src/lib/board/hid/report-map.js` | HID Report Map parsing |
| `src/lib/board/i18n.js` | UI strings (English and Korean) and language selection |

## Language

English by default, Korean as a second language: `?lang=en|ko`, otherwise a browser language starting with `ko`
picks Korean. All strings are in `src/lib/board/i18n.js` (same keys per language, `t(key, params)`);
`test/i18n.test.mjs` checks that keys and placeholders match.

## Known limitations

- Only devices that connect after the page has loaded deliver their Report Map to the input monitor (in the app,
  the page loads when the app starts).
- The Claude desktop app's built-in browser has no Web Serial picker; use the bridge or the app.
